# KillingCard: studio head feedback, 17 Nov 2026

The head's notes, applied:
> Every tip should have a clear highlight and link to the thing it's explaining. The UAV should show the
> exact cards, not just the name. For a first playthrough, skip the operator selection and killstreak
> selection screen. The scoring should be at the top of the battlefield area with a nice clear line of
> progress. There shouldn't be any impact of being first, so remove that part. Movement should allow
> going anywhere. The round recap at the bottom is overwhelming: we may not need it.

Tests: 798 → 803, all green. The new checks are in `tests/test_feedback_nov17.gd`; the rule checks are in
`test_rules_round.gd` and `test_rules_modes.gd`. Screenshots (before and after, at 844x390, 390x844 and
1280x720) come from `tests/tools/shot_feedback.gd`.

## 1. Tips: a clear highlight and a link

What changed:
- **The highlight.** Every callout puts a thick amber ring with a soft pulsing glow around its target.
  The rest of the screen is dimmed (50 % black). Text is still readable through the dim.
- **The link.** An arrow (a leader line with an arrowhead) runs from the bubble's edge to the ring. It has
  a dark outline, so it reads over any art. The bubble keeps 30 px clear of the target to leave room
  for the arrow.
- **No tip without a target.** A concept whose anchor is missing, hidden or empty no longer opens as a
  centred bubble. It waits, is not marked seen, and comes back when its target is on screen.
- **Exact anchors.** Each tip now points at the one thing it explains:
  - "Win the match" points at the new score race.
  - Incoming and Spotted point at the slot itself, not half the column.
  - The firefight tip points at the two front units of a column where both sides have units. It waits
    until such a column exists.
  - The match no longer hands the guide any tip anchored to the whole board (the old "New: X" path).

Unchanged: tips still never pass input through, and the at-most-4-per-beat pacing is the same.

Tests:
- `test_every_tip_in_a_scripted_match_points_at_its_target` plays three Deploys at 844x390 and 390x844.
  It drains every queued tip. For each one it checks four things:
  - the target is real and on screen;
  - the arrow ends on the ring;
  - the arrow leaves the bubble's edge and is long enough to see;
  - the bubble does not cover the target.
- `test_no_anchor_no_tip` and `test_connector_geometry` cover the rest.

## 2. UAV: the exact cards

When recon reveals the rival's plays, the incoming slot now shows the real card instead of a name on a
card back. Recon here means Recon Drone, Callout, Recon Specialist or Floodlights.

- **What the card shows.** It is the same banner as on the board: art, cost (always shown on a spotted
  card), FP, Armor, keyword icons and the trait.
- **How it is marked.** A dashed red frame and a SPOTTED tag say the card is not on the board yet.
- **Inspect.** A long press or right click opens the full card inspector, with the line "Spotted by your
  recon: it arrives in column X at Reveal". This also works for the rival Operator.
- **On phones.** It is a full 216x54 banner on a 844x390 phone, and the inspector has all the detail.
- **The tip.** A new "Spotted" concept explains it once, anchored to the first spotted slot.

Code: `MatchSnapshot.spotted_cards()`, `BannerView.show_spotted()`, `UnitSlot.show_spotted()`, and
`MatchController._open_spotted()`.

## 3. First playthrough: no setup screens

**On a first playthrough**, START NEW RUN skips both setup screens and goes straight to the run map. A
first playthrough means no run finished yet and the quick start not used before. The run starts with the
beginner kit:
- the starter Operator, Kestrel AR-7, which is the plain assault rifle with no extra rules;
- the starter killstreaks, the set the config already pre-picks.

Code: `RunState.first_playthrough()` / `quick_begin()`, called from `title.gd`.

**It is remembered.** `Settings.quick_start_done` is saved with the other options, through SaveMirror on
the web, so a crash-reload keeps it.

**From the second run on**, START NEW RUN opens the Operator and killstreak screens as before. Their
concepts ("starter", "loadout") are explained then, the first time each screen is seen. A player who has
already finished a run always gets the screens.

The boot smoke (`kcboot.js`) now clicks through those screens only when they appear.

## 4. Score: a race over the board

The score now sits right over the board, as wide as the board. The new widget is `score_race_bar.gd`:

`YOU 3 [■■■□□□]  TO 6  [□□□□■■] 2 RIVAL`

- **Two bars.** Each bar has one segment per point and fills toward the target in the middle. Yours is
  teal and fills from the left. The rival's is red, hatched (so it reads without colour), and fills
  from the right. First to the middle wins.
- **Numbers at the ends.**
- **When points land.** The bars slide to the new score, and a brief amber "+N" pops by the number of
  whoever scored. This happens at the Score step, during the playback. The playback holds on it for a
  beat.
- **Inspect.** Tap, long press or right click opens the score rules.
- **Original styling.** It uses the project's own palette and Barlow fonts. There are no Call of Duty
  logos, fonts or names.

Removed:
- The left rail's SCORE badge (R1 / score / TO 6). That slot is now **R# / LOG**.
- The score flyout (the ScoreBar).

**Trade-off.** The race needs 24 px over the board on a phone and 40 px on desktop, so the banners got a
little smaller:
- phone: 228x57 → 216x54;
- desktop: 304x76 → 296x74.

The hand tray got wider in return. The board's slot pitch is now 41 pt (it was 43 pt). Open question 1
asks whether that is acceptable.

## 5. "Being first": what initiative did, and the new rule

### What initiative affected before

**Who had it.** The side behind on the mode score. On a tie, the player (`ModeRules.tiebreak = player`).
It was recomputed at every Reveal. The chip showed it from round 2 of a run.

**What it changed:**
1. **Fields.** The initiative side's Fields were placed and resolved first, with their eliminations
   right away.
2. **Arrivals.** The initiative side's units, Operator placement, Rotations and Agile moves arrived
   first. Their On Deploy effects resolved and their kills were removed before the other side's units
   were even on the board. So:
   - the first side's On Deploy could never hit the other side's new arrivals;
   - the second side's On Deploy could hit the first side's arrivals.
3. **Tactics and loadout items.** All the initiative side's plays resolved first, and each play's kills
   were removed at once. So:
   - a first-side damage tactic could kill a unit before the rival's buff, heal or move on it landed;
   - the rival's play then fizzled.

   This is the "advantage of being first" the head felt.
4. **Killstreak strikes** (Mortar, Attack Helo). The initiative side's strikes hit first at Firefight
   step 0.
5. **Eliminations.** The initiative side's On Down / On Eliminate triggers resolved first.
6. **End of round.** The initiative side's End of round effects (Fields, units, perks) resolved first.
7. **Firefight beats.** The initiative side was only listed first. The two front shots were already
   simultaneous. The old inspector line "in each firefight beat your shots go first" was wrong.
8. **No effect on:** scoring, ties or match end, red dots, the AI's planning, and the First Shot
   keyword. First Shot is a card keyword, not initiative, and is unchanged.

### The new rule: both sides at once

Every step both sides take part in now resolves simultaneously:
- the Reveal's Fields;
- arrivals, then every On Deploy, then the traps they set off;
- tactics and items;
- End of round effects;
- On Down / On Eliminate follow-ups.

Two rules make that deterministic and side-free:
- **Nobody is removed until the step is over.** A unit downed in a step still gets the rest of that
  step's effects, like the two shots of one firefight beat. So a card can no longer "kill it before it
  acts".
- **Help before harm.** All effects that only help (buffs, heals, Cover, moves, draws, summons) go
  before all effects that harm (damage, Cover / First Shot removal, Field destruction, anything aimed at
  the other side).

  A helping play only touches its own side and a harming play only the other. So once deaths wait for
  the step's end, the order of the two sides cannot change any outcome. The fixed listing order (player,
  then rival) is just the event order.

  Help-first was chosen over "harm first" so that a buff, heal or move is never wasted on a unit that
  only died because of the order. The rule is the same for both sides.

Why this rule: both sides commit face down and reveal together, so "at the same time" is what players
already expect. The READY tip now says so ("Both sides' cards go off at the same time (nobody goes
first)").

**One exception: killstreak strikes** at Firefight step 0 still resolve one at a time:
- earlier rounds' strikes first;
- then this round's, the player's listed first.

A strike only hits the other side, so the order cannot change what a strike hits. The only knock-on is an
On Down set off by a strike kill.

### Removed

- `MatchState.initiative` and the INITIATIVE event.
- `MatchHooks.initiative_side`, and the `ModeRules` tie rules (`tiebreak`, `coin`).
- `EventBus.initiative_changed`.
- The initiative chip (`initiative_chip.gd`), the SCORE flag, the initiative inspector, the initiative
  concept (tip and Glossary), and the snapshot's initiative block.
- The tools' `tiebreak=` option. It is ignored now, with a warning.

**Card keywords that depended on it: none.** Every card, Field, killstreak and perk text was checked.
"First Shot" is a keyword. "Your first unit there" (Callout) and "the first unit each side brings here"
(Minefield) are per side. No reword was needed.

## 6. Movement: any column

Operator Rotate, Agile orders and Flank Route (every MOVE_UNIT effect) now reach any other column. The
far flank A ↔ C is included.

**One move order per unit per round.** A second Flank Route on a unit that already has a move this
Deploy is refused (`already_moved`). Before, adjacency refused it.

Updated to match:
- the rules (`MatchState.can_move_between`, `EffectResolver._move`);
- the AI's move candidates (all columns);
- the drag / tap targeting (`MatchSnapshot.can_move`): every reachable column lights up "ROTATE HERE" /
  "MOVE HERE";
- the texts: Flank Route, Agile, the Move tip, the Glossary, the hints and the inspector line;
- the refusal texts: the `not_adjacent` refusal is gone.

## 7. The round recap: removed

The panel at the bottom of the board is gone, with its tap-to-close behaviour and its tests. Nothing in
Settings or the tips referred to it any more.

What happened stays clear where it happens:
- each column that scores pops **"+1 YOU"** or **"+1 RIVAL"** over it (Hot Zone +2), for both sides;
- the score race fills and pops "+N";
- damage numbers, elimination stamps, the killfeed and the streak / killstreak toasts are unchanged.

The short "Round N: play cards, then READY." toast stays.

The details are optional. The **LOG** badge (where SCORE was) opens the round log. For each round, newest
first, it shows:
- who held each column and why;
- the points;
- the losses.

It keeps the last 8 rounds.

## Simulations

All runs use the shipped data and AI, with no tuning.

Tools:
- `tests/tools/balance_sim.gd` (seeds=160, runs=400, competent and casual proxies);
- `synergy_check.gd` mirror (seat balance, n=2000);
- `duel_sim.gd`.

"Adjacent" is a sim-only variant: the new simultaneous resolution, but with moves still limited to the
next column. It isolates the two rule changes.

| | before | adjacent (initiative removed only) | after (both changes) |
|---|---|---|---|
| Competent: run win | 40 % (158/400) | 40 % | 39 % (157/400) |
| Competent: in-run match win | 74 % | 74 % | 73 % |
| Casual: run win | 30 % (118/400) | 29 % | 29 % (115/400) |
| Casual: in-run match win | 59 % | 59 % | 60 % |
| Rounds per match (competent / casual, starter kit) | 6.08 / 6.25 | 6.08 / 6.25 | 6.00 / 6.33 |
| Run length (median, competent) | 23.1 min | 23.0 min | 23.2 min |
| Mirror seat 0 (starter / late decks) | 50.6 / 48.6 % | — | 50.4 / 48.8 % |

What the numbers say:
- **Removing initiative changes nothing measurable.** Same win rates and match length.
- **Moves to any column** leave run win rate, length and seat balance unchanged.
- **One starter-kit match swing.** The M3 rusher Firefight match with the bare starter kit drops for
  the competent proxy, 60 → 34 % (casual 31 → 44 %). The rusher squad's AI uses the long moves well.
- **Inside a real run that match is unchanged:** 89 % → 89 % for the competent proxy.
- **Duel** (presets and modes, n=120) stays within noise. Seat 0 was 52.5 / 54.2 % and is now
  55.8 / 56.7 % (ZC / FF).
- **Nothing broke, so nothing was rebalanced.**

## Open questions

1. **Banner size vs the score race.** On a phone the race costs 3 px of banner height (228x57 → 216x54).
   The slot pitch drops from 43 to 41 pt. Is that acceptable? The alternative is a thinner objective row
   between the two halves.
2. **Long moves and the rusher.** The rusher squad uses any-column moves well in the starter-kit
   Firefight match (competent 60 → 34 %), though not in real runs. Keep it, or limit the Agile free move
   to the next column (cards still go anywhere)?
3. **The round log.** It keeps 8 rounds behind LOG. Should the LOG badge also flash for a second after
   each round, so players learn it is there?
