# CallingCard playtest logs

Exported playtest logs for the cc18 internal playtest of Banner Wall.

## What goes here
- **Real logs:** put each tester's download (`callingcard-playtest-<date>-<sid>.json`) straight into this folder, unchanged. One file per tester download is fine. If a tester sends two downloads from the same device, keep both; the tool removes the duplicates.
- **`kpi/`:** the KPI sheet the tool writes (`kpi-sheet.md`, `kpi-sheet.csv`). It is regenerated, so don't edit it by hand.
- **`synthetic/`:** **SYNTHETIC test data, not playtests.** These files are generated by `tools/synthetic_playtest_sessions.gd`, which drives the real logger with scripted events, a simulated clock and a patched device. Every file is named `SYNTHETIC-*` and carries `"synthetic": true`. The KPI tool leaves them out unless you pass `--include-synthetic`, and the sample sheet built from them is `synthetic/kpi-sheet-SYNTHETIC.md`. **Never quote these numbers.**

Logs from the Studio Floor chat: save the attachment here with its original file name.

## Privacy
The log holds a random session id, device class, browser family, game events and the survey answers, including an optional free-text answer of up to 500 characters. It holds no names, accounts, IPs or locations. Before committing, read every open answer (shown in the KPI sheet under "Open answer"). If one contains personal details, remove that text from the `open` field and say so in the report. If a tester asks for their log to be deleted, delete the file and regenerate the sheet.

## Make the KPI sheet
From `projects/callingcard/`:
```bash
python3 tools/kpi_sheet.py playtest-logs/                 # every real log in this folder -> playtest-logs/kpi/kpi-sheet.md + .csv
python3 tools/kpi_sheet.py playtest-logs/ --unit session  # treat every session as its own tester
python3 tools/kpi_sheet.py playtest-logs/synthetic --include-synthetic --out playtest-logs/synthetic/kpi-sheet-SYNTHETIC   # tool test only
python3 tools/test_kpi_sheet.py                           # the tool's self-test
```
The tool uses only the Python standard library (3.9+). It checks every line against the schema in `source/project-callingcard/autoload/playtest_log.gd`, which is the same source the game uses. It reads `.json` downloads and raw `.jsonl` logs, recovers what it can from a cut-off file, and reports empty and consent-off logs as "no data" instead of guessing. Recipes and bars are in `documentation/production/playtest-log-schema.md` §5. The results go into `documentation/production/reports/internal-playtest-report.md`.

## Regenerate the synthetic logs
From `projects/callingcard/source/project-callingcard` (Godot 4.4.1):
```bash
godot --headless --path . -s ../../tools/synthetic_playtest_sessions.gd -- --out=../../playtest-logs/synthetic
```
It writes personas A (menu entry, desktop, full run), B (Find a Match entry, phone, slow load, D1 cleared slowly), C (menu entry, phone, partial: survey skipped, D1 not cleared, no quit line) and D (consent off, empty). It never touches a real log or save.
